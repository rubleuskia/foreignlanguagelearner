# Быстрый словарный индекс и счётчики в библиотеке

Дата: 2026-10-19. Статус: реализовано в `codex/vocabulary-index`.
Документ уточняет хранение и производительность из `READING_VOCABULARY_ARCHITECTURE.md`.
Продуктовые правила чтения и формат переносимого бэкапа v3 сохраняются.

## 1. Виджет строки книги

Непрочитанная книга: **New words: 1 240**. Явно прочитанная целиком: **Words: 18 430**.
Это число уникальных словоформ, а не вхождений. Accessibility-label поясняет это.
Это элемент списка приложения, не WidgetKit.

- Частично прочитанная книга показывает оставшиеся новые формы. Изучение главы влияет также на другие книги того же языка.
- Все главы прочитаны ≠ вся книга явно прочитана: общий TXT может содержать дополнительные слова.
- Пока индекс строится: Counting words…; при обработке знаний: Updating…; ошибка имеет Retry. Неизвестное число не выдаётся за ноль.
- Множество книги — весь TXT плюс все доступные субтитры. Импорт, строка библиотеки и подтверждение книги теперь используют одинаковое покрытие. Открытый документ читалки имеет собственную статистику.
- Слова удалённой книги остаются изученными. Карточки словаря не влияют на знания.

## 2. Диагноз предыдущей реализации

`Set.subtracting` уже исключал попарный перебор всех слов книги и знаний; доказанного O(n²) здесь не было. Затраты создавали повторная токенизация при подтверждении, загрузка всех моделей слов после каждого сохранения, создание модели на каждую изученную форму и оформление всех вхождений текста на MainActor.

Старый benchmark на 9,9 МБ содержал только шесть разных форм. Он не измерял стоимость хранения большого разнообразного словаря. Новые проверки используют 50 000 разных форм и 100 книг с общим словарём.

## 3. Прямой и обратный индекс

`VocabularyIndex` — actor, владеющий отдельной SQLite-базой. Все его SQL-запросы, чтение файлов и токенизация выполняются вне MainActor.

- `word(id,language,form)` с UNIQUE(language,form) задаёт локальные числовые ID.
- `known(word_id PRIMARY KEY)` — производная копия накопленных знаний.
- `source(id)` и `source_form(source_id,form)` сохраняют уникальные формы источника.
- `book(id,language,revision,total_count,new_count)` хранит готовую статистику.
- `book_word(book_id,word_id)` с уникальным составным ключом хранит прямой индекс.
- Индекс `book_word_by_word(word_id,book_id)` — обратный индекс.
- `book_source(book_id,source_id)` позволяет удалять больше не используемые кэши источников.

`newCount = |W_book \ K_language|`. При добавлении изученных форм `Δ` создаётся временная таблица только действительно новых wordID. Один агрегирующий запрос получает число этих ID в каждой затронутой книге. Счётчик каждой такой книги уменьшается на это число. Копия знаний и счётчики сохраняются одной SQLite-транзакцией.

Повторная доставка той же Δ ничего не уменьшает. 1 000 повторений слова в тексте — одна связь с книгой. Языки разделены. GROUP BY выполняется по обратному индексу, а не через чтение файлов или сравнение всех пар книг.

## 4. Источник истины и восстановление

SwiftData остаётся единственным источником истины для знаний, completion flags и словаря. SQLite — полностью восстанавливаемая проекция, исключённая из системного бэкапа. Код не обращается к внутренним таблицам SwiftData через SQL.

Перед публикацией статистики при запуске/после restore actor получает согласованный снимок знаний. Во временной таблице строится набор его wordID; разница с `known` применяется через тот же обратный индекс. Если знания не изменились, memberships книг повторно не обходятся. Уже сохранённые source/book индексы используются без токенизации.

Во время обычной сессии `ReadingVocabularyStore` накапливает только Δ успешных сохранений. `refreshLibrary` доставляет её actor, затем публикует маленькие summary DTO. После успеха доставки Δ удаляется из очереди. Ревизия знаний и поколение задачи предотвращают публикацию устаревших результатов; повторное применение идемпотентно. Изменение только знаний не повторяет обход/хеширование источников уже готовых книг.

Если приложение завершилось после SwiftData commit, но до обновления SQLite, следующий запуск восстановит пропущенную разницу из снимка. При ошибке SQLite подтверждённое прочтение не откатывается и не выдаётся за неуспех; статистика показывает ошибку/ожидание. Retry удаляет только производный индекс и строит его заново. Исчезнувшие книги удаляются из индекса; знания сохраняются.

**Отличие от первоначального проекта:** отдельный долговечный outbox/watermark не добавлен. При текущем локальном однопользовательском хранилище сверка снимка на запуске плюс идемпотентная Δ в живой сессии обеспечивает восстановление без второго журнала. Цена запуска — проход по K, но без чтения всех текстов. Если эта цена станет узким местом, следующим этапом может быть checkpoint по идентификаторам неизменяемых knowledge batches.

## 5. Компактное атомарное сохранение знаний

`ReadVocabularyBatch` — добавленная SwiftData-модель: UUID, язык, JSON массива форм, дата первого изучения, версия tokenizer. Новая Δ кодируется вне MainActor порциями до 2 048 форм. Для 50 000 форм создаётся 25 объектов вместо 50 000.

Короткая запись batch-объектов и completion flags остаётся **одной транзакцией существующего main ModelContext**. До неё сбрасываются несвязанные изменения позиции. Во время мутаций нет await. После неудачи rollback сопровождается восстановлением наблюдаемых flags, как в предыдущей реализации. Кодирование выполняется до мутаций, после await повторно проверяются знания, источник, язык и существование книги.

Старые `ReadVocabularyWord` продолжают читаться; массовая перезапись существующей базы не нужна. `ReadingKnowledge.forms` объединяет старые записи и batches. `ReadingKnowledge.words` — граница совместимости для export/restore: объединяет формы и выбирает самую раннюю дату, не меняя сохранённые модели во время чтения.

Restore группирует новые знания по языку и дате, сохраняет batches в той же транзакции, что словарь. Более ранние даты старых одиночных записей обновляются с поддержкой rollback. Повторный restore не дублирует знания. V3 по-прежнему содержит формы и даты, а не локальные wordID, batches или счётчики. V1/v2 и translations-only знания не изменяют.

**Отличие от первоначального проекта:** отдельный writer actor для всей библиотеки не введён. Уменьшение числа сохраняемых моделей устраняет главную стоимость completion и сохраняет уже проверенную координацию с playback. Перенос записи в другой контекст без переноса всех писателей опасен потерей flags из устаревшего массива tracks. Начальная загрузка знаний выполняется отдельным read-only контекстом вне MainActor. Большой restore/export всё ещё может занять основной поток; это явно не объявляется полностью решённым этим изменением.

## 6. Кэш источников и подтверждения

`ReadingTextSource.cacheKey` включает версию parser/tokenizer и:

- для legacy inline text — SHA-256 точного текста;
- для управляемых файлов — путь, расширение, размер, время изменения/создания и inode.

Приложение не редактирует импортированные файлы. Метаданные проверяются до и после чтения; изменение инвалидирует результат. Изменения, специально сохраняющие все метаданные, этим кэшем не обнаруживаются: это не проверка целостности против подмены файлов. При добавлении редактора источников обязателен явный sourceRevision и запрет модификаций без его смены.

Первый анализ читает/парсит источник и сохраняет unique forms. Повторный prepare/complete читает эти формы из индекса вместо повторного разбора текста. Fingerprint proposal идентифицирует набор источников. Смена источника, языка или числа добавляемых форм требует нового подтверждения. Глава без субтитров имеет пустой набор; общий TXT не делится на предполагаемые главы.

`indexBook` собирает уникальное объединение источников. Membership и статистика публикуются атомарно относительно текущего `known`. Actor сериализует финализацию импорта с Δ; знание, пришедшее во время построения, учитывается либо при финализации, либо последующим обновлением. Ошибка чтения не заменяет готовый индекс частичным набором.

Импорт ZIP учитывает TXT и субтитры, хранит краткоживущий кэш предварительного анализа в `BookImportService`; fingerprint объединения не зависит от порядка перечисления файлов. Финальная скопированная версия проверяется до сохранения книги.

## 7. Подсветка большого документа

`VocabularyTextIndex` — независимое неизменяемое представление для UI: таблица уникальных форм и массив `(startUTF16,lengthUTF16,formID)` вместо отдельной строки на каждое вхождение. Индекс строится вне MainActor; дисковый кэш привязан к SHA-256 точного отображаемого текста и версии tokenizer. В бинарном plist позиции записаны тройками UInt32 (12 байт на позицию), при чтении проверяются границы, порядок и ID. Кэш очищает старые файлы при превышении 128 MiB; один текущий файл сохраняется, даже если он превышает этот бюджет.

`TranscriptTextView` определяет видимый диапазон с запасом в половину экрана, бинарным поиском находит начало позиций и проверяет известность только слов этого окна. Отрисовка ограничена этим окном, максимум 4 096 неизвестных диапазонов. `TranscriptLayoutManager` рисует цвет, подчёркивание и фон реплики без изменения NSTextStorage: обновление оформления инвалидирует только display и не сбрасывает прокрутку. При уходе окна предыдущие диапазоны инвалидируются для перерисовки. Изменение языка, версии знаний, переключателя и Dynamic Type инвалидирует оформление. Native selection откладывает обновления; cue background и following остаются независимыми.

Для follow больше не запрашивается layout всего text container, только диапазона начала реплики. Сам UITextView по-прежнему получает полный текст. Полная виртуализация текста, фонового layout и выделения между страницами не реализована; её необходимость следует оценивать на физическом устройстве.

## 8. Сложность и границы

Обозначения: T — объём текста, U — уникальные формы книги, K — знания, B — книги, M — все уникальные связи книга—слово, P(Δ) — связи затронутых новых изученных форм.

| Действие | Работа |
| --- | --- |
| Первичная токенизация | O(T), один раз на версию источника |
| Построение membership | O(U log V) с B-tree, V — локальные формы |
| Получение начального newCount | U индексированных проверок known |
| Обычное обновление знаний | обработка Δ и P(Δ), плюс SQL lookup/aggregation и запись затронутых строк |
| Сверка знаний при запуске | O(K log V) для снимка; membership обходится только для отличий |
| Чтение готового summary строки | O(1) по DTO; список O(B) |
| Оформление окна | O(log N + n_visible), N — позиции текста |

Хранение: O(M + K + source memberships), позиции O(N) на диске/в памяти открытого документа. SQLite хранит индексы B-tree: не обещать строго O(Δ) для всего SQL-запроса. В худшем случае общие слова встречаются во всех книгах, и P(Δ) велико. Таблицы всех пар книга—книга нет. Bitmap/Roaring не требуется для текущего масштаба; добавлять только после измерений.

## 9. Карта кода и проверки

- `VocabularyIndex.swift`: SQLite actor, source cache, memberships, reconcile/learn, rebuild.
- `ReadVocabularyBatch.swift`: компактное основное хранение, совместимость со старыми записями.
- `ReadingVocabularyStore.swift`: orchestration, Δ, публикация summaries, подтверждение.
- `VocabularyTextIndex.swift`, `VocabularyTokenizer.swift`: компактные позиции и дисковый кэш.
- `ContentView.swift`, `ReadingVocabularyViews.swift`: виджет списка и состояния загрузки.
- `TranscriptTextView.swift`: окно оформления, follow, selection.
- `DictionaryTransferService.swift`: переносимые знания, даты и атомарный restore.

`VocabularyIndexTests` проверяет эталонное пересечение Set после серии обновлений, разделение языков, идемпотентность, промах доставки между primary/projection commit, повторное открытие без токенизации, потерю и rebuild индекса, изменения/отсутствие файлов, Unicode-позиции, 50k разных форм с компактным сохранением и восстановлением, 100 книг с 100k затронутых postings. UI-тест проверяет смену счётчика новых форм на общий после полного прочтения. Результаты и ограничения замеров — в `READING_VOCABULARY_VALIDATION.md`.


### Исправление прокрутки (2026-10-19)

Повторный layout из-за изменения расчётной высоты текста больше не запускает follow для той же реплики. Реальные изменения размеров экрана, текстовых отступов, Dynamic Type и явный Follow audio продолжают пересчитывать цель. Список глав вынесен из постоянно обновляемого Menu в отдельный List со снимком строк; изменения playback.lastPosition не меняют открытый список.
